# DODO MCP 1.10.0 — Media recovery, private startup and safe upgrades

This release fixes the reported Creative Media failures and upgrade diagnostics,
and adds recovery paths for already-paid work. Global media remains usable from
chat without a project, and the calling AI keeps per-request model selection.

## Upgrade and identify the running server

```bash
npm install -g dodo-mcp@1.10.0
dodo status --json
```

Restart the intended service using its actual absolute entrypoint and the same
`DODO_CONFIG_DIR`, then reconnect/rescan MCP to load updated schemas. A different
CLI version in PATH does not change an already-running process or a service with
a fixed executable path. Owner status compares CLI/runtime version and package
paths. MCP overview/media status include `serverVersion`, and the safe startup
identity line remains visible under `--quiet`. `/healthz` also reports version.

Normal upgrades preserve OAuth login. Before DB/schema/version changes, DODO
creates a private installation checkpoint. A checkpoint failure stops migration.
Global config writes are staged, flushed and atomically replaced; `doctor` reads
state without migrating it. Unknown security config fields are still rejected.

## Private Local Config access

Startup logs no longer receive capability URLs or pairing codes, including quiet
and redirected starts. Retrieve owner access explicitly:

```bash
dodo web --local
# For automation, write to a new private file instead of stdout:
dodo web --local --output-file /absolute/private/path/config-access.json
```

Issuing a fresh local link revokes the previous local session. Non-interactive
retrieval requires a private output file; ordinary status output contains no
access token. STDIO stdout remains MCP protocol data. Treat explicitly obtained
access details as secrets rather than placing them in logs.

## Diagnose and recover creative work

`creative_job` retains bounded, redacted `diagnostics`: HTTP status, provider code,
message, request ID, retry-after, dispatch phase and whether the outcome was
rejected, not sent or unknown. Clear quota/rate-limit rejection becomes failed;
a lost response after sending remains uncertain. The submission audit receipt
means accepted, while separate lifecycle events describe the final outcome.
Do not infer credits or billing from an HTTP code alone.

`multimodal_status` reports local readiness/blockers and does not contact a model.
Creative Media's **ทดสอบการเชื่อมต่อ (ไม่สร้างภาพ)** checks credential/model metadata,
latency and timestamp. It neither generates media nor proves inference, image
support or account credits.

Two new global operations are available directly in Full or through `dodo_media`:

```text
dodo_media(operation="creative_jobs",args={limit:25})
dodo_media(operation="creative_jobs",args={idempotencyKey:"original-request-key"})
dodo_media(operation="creative_job_control",args={jobId:"creative_…",action:"retry_save"})
```

MCP history and key lookup show only the caller's jobs. The private owner web
history defaults to Global and can select a registered project to inspect client
jobs in that namespace and apply explicit recovery/tracking controls through its
authenticated owner session. Project access is revalidated before operating on
its jobs. Retry with the same key and
arguments can recover the same submission across a restart without another paid
POST. `retry_save` finalizes existing staged/generated bytes and repairs the
artifact/receipt association; it never starts another render.

The backend reserves bounded output/ref capacity before spending, preserves
recoverable output if final bookkeeping fails, and reconciles persisted artifacts
after restart. An access token expiring after acceptance does not discard the
result; collection with a renewed token still checks the live grant/client and
scope ceiling. Revoked authorization does not regain access.

Completed/failed history no longer consumes the active-work limit as a hidden
32-jobs-per-day gate. Stale remote statuses are reconciled before refusing a full
queue. Unfinished jobs are retained separately from terminal history rather than
being silently deleted at 24 hours. Cosmetic connection changes and defaults for
new jobs do not block collection of an existing video, while endpoint/protocol/
account changes remain checked.

`creative_job_control(action="stop_tracking")` stops local tracking or waiting.
It is not a provider-confirmed cancellation and does not promise a refund or that
remote rendering stopped. Failed/uncertain paid work is never automatically
resubmitted with a new model or idempotency key.

Background media/CAS cleanup reports maintenance failures and uses retryable
metadata/file finalization without crashing unrelated server operations.

`media_save` preserves POSIX file permissions when overwriting existing media
and rolling back the change, without treating file-type bits as permissions.

## Settings and model discovery

`POST /api/ai/media` merges only fields present in the owner request. Omitted
fields preserve the saved values; explicit `connectionId:null` clears selection.
State returns `revision`; the web UI sends `expectedRevision` and receives HTTP 409
for stale changes rather than overwriting another tab. The audit records actor,
revision and changed field names, without credential/endpoint values.

A provider save followed by failed media selection reports the provider as
committed instead of implying both operations failed. Typed API keys remain in
the form when local validation fails and are cleared immediately before a real
submission. Existing keys are never populated from the server.

Model discovery follows supported upstream cursors/page tokens, bounded to 10
pages, 2,000 IDs and 8 MiB per collection. Results expose `truncated` and provider
page counts when incomplete. Oversized or URL-shaped IDs are rejected, not
silently clipped into IDs the provider never advertised. Name hints remain
unverified suggestions; explicit supported model IDs still work without a list.

## Offline installation restore

```bash
dodo state list
dodo state inspect <checkpointId>
# Stop all DODO processes sharing this installation first.
dodo state restore <checkpointId> --hash <manifestHash> --yes
```

Checkpoints include a WAL-consistent DB snapshot, raw config, owned Env credential
files and signing/cookie material with hashes/private permissions. They retain
up to the latest five complete checkpoints, keep an emergency state before
restore and resume an interrupted restore journal before normal boot. Restored
OAuth grants/tokens/sessions are revoked to avoid reviving old access; sign in
again after restoring. External Env and OS-vault values are not exported or
modified. Project files and generated-media bytes are outside these snapshots.
See [Recovery](RECOVERY.md#installation-state-checkpoints-1100) before reverting.

Full now contains **176** capabilities (**172** by default); Compact remains
**20** and Hybrid **49**. See [Creative Media](CREATIVE_MEDIA.md),
[AI Providers](AI_PROVIDERS.md), [Security](SECURITY.md), and the measured
[Test report](TEST_REPORT.md).
